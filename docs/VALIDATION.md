# 验证与发布条件

程序测试和模型评估是两种不同证据。程序测试通过，不代表模型在真实争议中准确，也不代表小红书页面采集完整。

## 可以复现的验证

- `npm ci --ignore-scripts` 安装锁定依赖。
- `node node_modules/playwright-core/cli.js install chromium` 准备浏览器（已有 Chrome 可省略）。
- `npm test` 验证引文、网址、额度、缓存、定向导入、内容修改、取消、同源检查、浏览器回复提取和评估统计；图片地址边界、附件发送、识别页码、证据来源、模糊降级、额度及图片缓存。
- 在 DSH 中安装包，刷新，点击侧栏「鲸声守望」，切换各标签，切回对话，再回到工作台。升级后端模块时还需重启 DSH。
- 导入文字，查看实际模型输出；点击已阅、恢复未阅并导出。
- 「示例评估」运行公开样例，导出完整报告。检查错误和未评估条数，不能只看符合条数。

构造页面和模型替身用于验证程序行为；公开样例使用真实模型，但仍不是实际平台分布。CI 配置已经提供，首次托管运行前不能声称 CI 已通过。

## 真实采集验收（需要用户登录）

1. 点击「打开采集浏览器」，在独立窗口登录小红书。
2. 扫描一个关键词，先设置1篇笔记、3条评论、4条分析。
3. 对照原网页确认：标题、作者、正文、评论原文和上级评论一致，子回复没有并入上级正文。
4. 在「查看配图与机器识别」逐页对照原图，核对转录、画面说明和不确定标记；核对评论分析是否保留引用关系。识别不完整不应显示整篇正常。
5. 点击一条记录的“已阅”，确认它从未阅各筛选中隐藏、可从已阅列表恢复；导出确认原文及模型依据保留。
6. 同一链接再扫描，检查去重和缓存；对真实修改的内容，检查旧判断撤回。
7. 在登录失效、验证要求、模型失败及中途停止场景下确认状态可信，本条自身未读的内容不能显示整篇正常；独立评论不应仅因所属笔记缺图变成信息不足。

只记录实际完成的项目。没有账号、未登录或被验证码阻挡时，结果记录为「未完成」，不能替换成构造页面验证。

## 样例统计的读法

预期标签由项目作者给出，按默认规则分为 normal（正常）、review（建议复核）、uncertain（信息不足）。输出经过逐字引文、分析对象、问题对象/行为及缺失信息校验后才进入统计。背景缺失仅在评论判断确实依赖该背景时导致信息不足；不会把所有独立短评一律降级。

- `agreed / attempted`：已尝试样例符合率，调用失败也在分母内。
- `falseAlerts`：正常样例被建议复核。
- `missedReviews`：应复核样例被直接判为正常。
- `matrix`：包括信息不足与调用失败的完整混淆矩阵。
- `unattempted`：未评估条数；额度不足或中途停止时报告不能标为完整。

不要把“应复核 → 信息不足”藏在漏报之外宣称零漏报；请同时提供混淆矩阵。要讨论真实准确率，后续需独立标注的实际样本、明确抽样方式及不同模型/规则的对照。

## 当前状态

当前版本为0.6.3，公开人工样例32条；65项程序检查通过。对一条实际群体不尊重漏判进行了定向实模重试，初判及复核都认定可疑，不据此推出整体准确率。当前32条样例尚未完成完整实模评估；历史版本的样例结果见 `docs/TESTED.md`，不能用于宣称当前版本全部样例通过。指定笔记采集已跑通；真实评论及回复关系的逐条核对、多篇采集等仍待扩展验证。定位为实验性插件，供试用与反馈。
