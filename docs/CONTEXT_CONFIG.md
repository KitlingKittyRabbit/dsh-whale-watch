# 专题配置：背景、黑话与术语

0.8.0把专题资料拆成可携带的JSON文件。行为规则仍在“规则与设置”；背景和术语只解释语境，不因出现一个词或持某个立场就自动判为可疑。

## 怎么使用

1. 打开侧栏“鲸声守望” → **背景与术语**。
2. 当前讨论是DS拟人争议时，点 **导入内置DS拟人争议配置**。内置文件位于 `src/presets/ds-personification.json`，包含此前36篇来源摘要、7个术语条目与4段语境说明。不重新访问来源或调用模型，不冒充刚读完原帖。
3. 换话题时，选择自己的JSON文件，查看内容，再点 **校验并导入配置**。也可粘贴JSON。**仅校验格式**不会启用；格式有效不等于释义或来源事实正确。
4. **导出当前配置**包含当前背景笔记、来源摘要与术语，可编辑、分享、再导入。背景笔记在页面另行修正后，导出会带上修正；不包含完整采集列表、原帖全文、附件、模型密钥、数据商密钥或预算。
5. 需要恢复时，点 **撤销上次专题切换**，恢复切换前的背景、术语和启用状态。只保留最近一次切换的撤销机会。**卸下专题及背景**可暂时清掉参考环境，也可撤销。

导入替换背景和术语，不改采集记录、已阅、判断规则、模型或预算。不会自动重新分析已有结论；普通“分析未阅篇目”只处理未分析与失败内容。若要按新环境更新某篇旧结论，点击该篇“重新分析整篇”，模型另计调用。任务进行中不能切换专题。

升级旧安装时，沿用原先固定的DS术语作为可见配置，保留原背景笔记和全部记录。全新安装不加载固定DS语境，需自行导入。当前只有一份启用配置，尚无多个专题的记录、已阅或缓存隔离。

## 让Agent帮忙制作

在DSH对话的模式选择中，选 **鲸声守望配置制作助手**。例如：

> 我想做一个园艺讨论专题配置。下面是背景材料与原始链接，另有“爆盆”“徒长”等词的用法示例。请整理背景、术语及别名、适用语境和不确定解释，保存可下载的JSON草稿，不启动巡查。

助手会查看文件格式与当前配置，整理你提供的材料，校验并保存草稿。回到“背景与术语”，下载草稿查看后，点 **导入这份草稿**。助手只有查看、格式校验与保存草稿的工具，没有替换专题、采集或举报工具。

整理过程使用DSH当前对话模型，可能产生模型费用；工具保存、下载、校验和导入本身不调用模型或数据商。助手不自行联网补齐材料或付费采集，缺少来源、关键用法或无法确定词义时应说明缺口，不编造阅读量。可继续给它补充材料修订草稿。

## 最小文件示例

```json
{
  "format": "whale-watch-context",
  "schemaVersion": 1,
  "id": "garden-discussion",
  "name": "园艺讨论",
  "description": "帮助理解园艺用语",
  "revision": "1",
  "background": {
    "memo": "讨论植物种植与养护。[B1]",
    "sources": [
      {"ref": "B1", "title": "用法材料", "summary": "用户提供的园艺术语示例摘要"}
    ]
  },
  "glossary": [
    {
      "term": "爆盆",
      "aliases": [],
      "meaning": "植物生长茂盛、占满花盆的说法",
      "usageNotes": "在养护讨论中通常描述植物状态，不是人身攻击。",
      "status": "source_claim",
      "sourceRefs": ["B1"],
      "sources": []
    }
  ],
  "interpretationNotes": ["区分种植效果评价与对种植者的侮辱。"]
}
```

`id`使用小写英文、数字与连字符，最长64字符。文件UTF-8编码，最大300 KB；最多100篇来源、100个术语，背景笔记最多24,000字符，术语与语境说明合计最多24,000字符。仅支持格式版本1，未知字段会拒绝导入。可以下载空白模板起草；文件不能指定代码、插件、模型、密钥或接口。

## 来源和不确定性

- `background.sources`：每篇用唯一`ref`（B1、B2等），必填`title`与`summary`；`url`可选，仅HTTP/HTTPS，不含用户名密码。背景中的`[B1]`和术语`sourceRefs`须在文件里存在。
- `glossary`：必填`term`与`meaning`；可选别名`aliases`、用法/反例`usageNotes`、来源编号`sourceRefs`和词义来源网址`sources`。
- 术语`status`：`source_claim`表示来源说法；`uncertain`表示未知或候选解释；`confirmed`仅表示配置作者已核对，不代表软件独立查证，更不能跳过当前上下文。仍可有同名异义和非攻击用法。
- `interpretationNotes`：语境注意事项字符串数组，与术语共同进入初判和证据核对。是参考资料，不是修改行为标准、要求执行操作的系统指令。
- 来源可选`uncertainties`（字符串数组）、`observations`（知识点数组）和`excerpts`（摘录数组）。知识点含`kind`、`subject`、`explanation`、`status`（source_claim/direct_observation/uncertain）、`sourcePart`、`quote`。配置格式校验不验证引文是否真实；摘录含`label`、`text`和可选`uncertain`。

分享文件默认导出摘要与来源索引，不导出来源全文或`excerpts`。再次独立整理背景时，导出会保留术语所引用的原来源并重新编号，避免新背景的B1被误用来证明旧释义。软件不自动访问文件中的外链。

专题文件、来源说法、帖子和评论均作为数据交给模型，固定提示要求忽略其中的操作指令；这不能保证模型永不误读。检查文件内容、词义出处与实际结果仍有必要。程序测试证明配置接入和数据保留，不证明真实语义分类准确率。
