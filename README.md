# 鲸声守望

**实验性 DSH 内容巡查插件。** 从 DSH 侧栏进入工作台，支持通过 SocialDataX 第三方 API 按篇读取小红书正文、配图、评论及回复，再结合已保存讨论给出复核建议；也保留浏览器采集。默认提供大肥鱼话题规则，也可以替换规则。

不是完整舆情数据库，不认定用户身份，不自动举报。支持保存配图、使用看图模型识别文字和画面，并供正文及所属评论分析使用；视频和音频未识别。结果及人工复核保存在本机；待分析文本、上下文与配图会发送到所选模型服务。

## 安装与试用

支持的宿主版本：**DSH Web `0.2.0-rc.2`**。本机验证环境为 Node 24、Linux、Google Chrome。其他系统和 DSH 版本尚未实机验证。

1. 在 DSH **插件 → 添加插件** 的“包名或地址”中填入 `https://github.com/KitlingKittyRabbit/dsh-whale-watch`，点击安装。仓库安装得到已推送版本；本机尚未发布的版本需使用本地安装包。
2. 安装后启用「鲸声守望」，按宿主提示刷新页面。升级已有版本时，先卸载旧包再安装；当前 DSH 的包替换还需要重启进程，以加载新的后端模块，巡查数据会保留。
3. 点击左侧 **鲸声守望**，主界面显示工作台。
4. 先在 **导入文字** 中填入示例，试用模型分析；使用 DSH 已配置的模型，不需要再填密钥。
5. 使用新 API 方式时，在 **规则与设置 → 数据来源与费用** 保存 SocialDataX API Key，选择该读取方式并保存设置。回到巡查页先填一篇笔记链接试用。浏览器方式仍需打开独立采集浏览器并登录小红书。
6. 阅读原文、配图、上下文和模型依据，点击「已阅」即可从当前列表移除；原文和模型结果保留，在「已阅」中查看，或「恢复未阅」。可导出JSON记录。

仓库地址安装需要仓库已经公开，并能正常连接GitHub。插件运行代码已包含在仓库中，没有额外的构建步骤。已在独立测试环境中通过DSH完成仓库地址安装；GitHub连接不便时，也可使用 [发布页](https://github.com/KitlingKittyRabbit/dsh-whale-watch/releases) 已发布的安装包，或本地打包生成的 `dsh-dafeiyu-patrol-0.7.2.tgz`，在同一个输入框填写安装包的本地绝对路径。

### API 按篇读取（0.7.0 实验功能）

这是独立的第三方数据服务，不是小红书官方接口。需要向 SocialDataX 获取 API Key；不向数据商提交你的小红书密码、Cookie 或浏览器登录状态。供应商收到搜索词、笔记链接/编号和分页请求。服务可用性、内容覆盖及授权状态不能由本插件保证。

1. 在 [SocialDataX](https://socialdatax.com/ai/) 获取密钥，在插件“规则与设置”填写并单独保存。密钥输入不会回显；请勿发到聊天或提交 GitHub。
2. 将默认读取方式选为 **SocialDataX API：按篇读取**，保存设置。默认每轮采集5篇、数据费用按当前价格限5元；分析也按篇控制，默认最多5篇，每篇包含正文及已保存评论。
3. 先指定一篇链接，勾选“仅采集”后点击读取，核对原文、图片、评论数量和回复关系。指定链接不额外搜索。确认材料后，点击“分析未阅篇目”使用已保存材料，不再调用数据商。
4. 下一轮可直接“按篇读取并分析”。接口分页会自动读取一级评论和回复；详情、评论和回复读取完毕后才开始模型分析。结果仍只有“可疑”和“其它”，不自动举报。

按供应商目前公开的价格，搜索、正文详情、每页一级评论、每页回复各10积分，即约0.10元/次；每页条数由服务返回，不假定固定20条。假设100条一级评论，每页20条且无回复，详情1次＋评论5次约0.60元；搜索和回复另外计费。**数据费用与 DSH 大模型、看图费用分开；按篇的分析上限不是模型金额预算，评论多的篇目会分批输出具体判断。**

默认5元限制最多50次数据请求尝试；连接失败也占名额，不自动重试。界面显示服务回报的已确认费用和待确认次数。发现单价与0.10元不同立即停止后续调用，但已发起的这次请求可能已经按新价收费；因此该限制按当前价格估算，不保证供应商改变价格后仍不超额。每次手动发起新的采集任务重新计算额度，离线分析不消耗数据额度。

笔记卡片列出实际返回评论数、接口标注数、分页是否结束及缺口原因。达到预算或用户停止后保留已读正文和评论；未读全的笔记不新增到已查缓存。后续重新读取部分笔记目前从第一页开始，仍可能收费；离线继续分析只处理保存材料。完整读取过的笔记默认跨任务排除，想更新新评论可取消排除。

为控制资源，一篇最多保存2,000条评论，正文及每条评论最多15,000字、每条内容最多18张配图；截断、漏图、视频/语音未识别均有标记。看图默认每轮最多5条含图内容，笔记和带图评论都占用名额，其余图片保留为未读取。隐藏、删除、接口未返回的评论不能当作已经看过。

模型每批判断最多10条目标，同时提供正文、配图机器读取及全部已保存评论；每个作者和上级关系分别标明，证据仍须属于目标本人。初步可疑逐条额外核对。已保存讨论超过90,000字符输入保护上限时，改为正文与相关讨论串，再必要时保留目标及上级链，界面明确标出未提供的评论数；必要材料仍过长则报错，不能宣称读过整区。批次输出限16,384 token、120秒，逐条证据核对限8,192 token、90秒。保存记录改变后旧分析需要更新，单条重试继续携带其所属讨论。

接口失败不会回退浏览器，也不会自动提高预算或循环重试。背景阅读仍是独立的背景整理流程，每篇最多选10条评论作背景样本；它与这里的整篇讨论判断不同。

**当前已核对供应商公开接口契约，分页、预算、取消、证据归属及整篇模型输入经过替身测试；尚未使用真实 API Key 验证商业接口的实际返回和覆盖。** 先试一篇并核对材料，再决定是否扩大使用。接口参考：[公开 OpenAPI](https://mcp.socialdatax.com/socialdatax/api/v1/docs/openapi.json)、[服务说明与价格](https://socialdatax.com/)。

### 浏览器采集（原有方式）

原帖优先通过「在采集浏览器查看」打开，复用采集窗口的登录状态；普通浏览器链接可能再次要求登录。可勾选「仅采集，暂不调用模型」检查能读取多少内容。

要求扫码或 App 查看且正文未展示的笔记会单列为未读取，不送模型分析。部分漏采显示「部分完成」，全部未读则显示「任务未完成」。此类内容需要在 App 中复制正文与上下文到「导入文字」；模型 API 不能解决网页访问限制。

遇到登录要求或验证码时任务暂停，由用户处理后点击「继续任务」。继续任务重新扫描入口，已保存的相同内容会去重并复用分析。

默认勾选「排除已查过的笔记」，按笔记编号跨任务跳过历史成功采集的笔记，不重复打开和分析，浏览器重启后仍有效。排除数单独显示，不占新笔记名额；搜索滚动有次数上限，未找到新笔记只表示本次范围内没有新增。未读成功的笔记会重试。要更新旧帖正文或新评论，取消勾选即可；导入文字的记录不作为成功采集历史。短链接需先正常跳转才能识别编号。

「清空已查缓存」清除用于跳过旧帖的历史，原文、模型结果和人工复核保留；相同文字仍复用模型分析。清理后重启不会从旧原文重新生成缓存，再次成功采集才写回。可「撤销上次清理」，恢复历史并保留清理后新增的已查内容。任务运行中不能清理或撤销。

浏览器方式默认每轮最多5篇笔记、每篇10条可见评论、55条内容分析，配平最多55条正文及评论。另最多读取5篇配图，每篇最多18张；看图1至3张单篇超时120秒、输出最多8,000 token；4张以上超时180秒、输出最多32,768 token，图片输入也可能收费。旧默认5/10/15会自动升级为5/10/55，自定义数量保留。单条内容分析超时90秒、回复最多8,192 token（模型思考也可能计入）。每条疑似问题额外做一次证据核对，每条文字分析最多两次模型调用；核对失败不会采纳初步指控。任务记录核对次数。失败调用也占用条数额度，条数上限不是金额预算。任务只有用户点击或对话指令发起时运行，没有后台定时巡逻。

如找不到浏览器，可以设置 `PATROL_CHROME_PATH` 后启动 DSH，指向自己的 Chrome/Chromium 可执行文件。

### 配图使用

在 **规则与设置 → 配图读取** 勾选读取配图。默认跟随内容分析模型，模型必须明确声明支持图片；也可单独选择已配置服务中的看图模型，文字分析继续使用原模型。不支持图片时会提示，不会把文字模型的占位响应当作看图成功。

识别文字和画面后再分析正文，评论也会补充所属笔记的配图语境。每条笔记的「查看配图与机器识别」可以逐页查看原图、转录、画面说明及不确定标记。机器读取不是人工验证，模糊或缺图时不能据此认定整篇正常。

仅采集只保存原图，不调用任何模型。相同附件和看图模型复用已有识别，规则变化不重复调用看图；每轮看图额度按含图内容计，失败也占额度，与正文/评论分析额度分开。图片下载、识别页码、已读取数量和不完整情况单独保留。采集前已存的旧记录没有原图，须取消排除已查重新采集才能读取。

### Agent 辅助入口

新建会话时选择 **鲸声守望** 预设，可以请求：

> 查一下大肥鱼、DeepSeek拟人的相关笔记，先看5篇，每篇读10条评论，重点关注骚扰动员，把原文和判断依据列出来。

Agent 调用固定的任务工具，任务后台运行并将结果保存到同一工作台。不会通过不断循环对话来操纵页面。工具：`patrol_start`、`patrol_status`、`patrol_results`、`patrol_mark_read`、`patrol_stop`、`patrol_clear_cache`、`patrol_restore_cache`。缓存清理和撤销须用户明确要求。只有用户明确要求后才标记已阅或恢复未阅。

模型分析失败时可点击卡片“重试这条”，只判断该记录，浏览器材料最多1条内容分析和1篇配图读取；API 材料带入该记录所属已保存讨论，并最多读取1条含图内容；已有配图识别可复用，成功记录不重跑。单条回复限额包含模型思考时，2,200 token可能耗尽后还没有完整结果，现默认提高到8,192 token。达到上限时不采纳半截输出，也不自动反复重试。

## 社区讨论规则与整理背景

默认规则已改为共同维护社区讨论与创作环境，适用于所有立场。七类行为是：侮辱性人身攻击及谐音、圈子整体贬损或地图炮、普通创作区引战、牵连无关角色或圈子、威胁或隐私侵扰、骚扰及报复动员、造谣歪曲或冒充。前两轮模型分析采用同一标准；普通创作区引战和牵连无关角色不要求先证明人身侮辱。既有自定义规则在升级时保留；在“规则与设置”中保存新规则才能用于当前实例。

在 **背景阅读 → 更换背景（可选） → 使用已整理的36篇背景** 启用扩大阅读整理，来源见 [背景指南](docs/BACKGROUND.md)。整理覆盖36篇可见笔记、533条采样评论、91张配图记录，含重复附件；标明缺页、未看视频和未确认术语。它是此前阅读的整理，不冒充本轮模型自动阅读。包内只含整理摘要、来源索引与链接；本机已有采集记录会关联原文，未采集的来源只提供摘要。整理中的主张不等于已核实事实，配图转录未完整时仍须核对原图。

启用时保留原背景历史，不改动原文、已阅状态或已查缓存；当前背景改变后，旧分析需要重跑，但不会自动调用模型。也可以按链接或关键词重新阅读文章并生成新背景；成功后会替换当前背景，不是自动追加到现有材料中。背景页默认先显示当前使用状态、工作方式；来源、编辑和更换操作折叠显示。程序测试只验证流程和数据，不等于已验证真实分类准确率。

## 结果分类与继续任务

界面结果只分“可疑”和“其它”。有具体问题依据的内容归入可疑；未发现具体问题或材料不足的内容归入其它，仍保留原因、缺失信息和原文。待分析和已阅是处理状态，不是第三种检查结果。旧数据与模型输出格式保持兼容。

停止或重启中断后的分析任务显示“继续分析剩余内容”，按原每轮上限处理，先跳过已阅及当前规则下完成的结果，避免再次调用模型或看图。没有可恢复任务时仍可点击“分析未阅篇目”开始下一批。登录暂停继续原采集任务；停止的采集任务若留有待分析内容，继续按钮先处理这些已保存内容，新增采集需重新发起巡查。采集去重按笔记编号工作，不是浏览器页码的精确断点恢复。背景阅读继续仍复用可用的阅读缓存；示例评估需要重新运行。

## 已阅与未做模型分析

默认列表只显示未阅内容。每条只有「已阅」按钮；已阅后隐藏，保存阅后时间，并在「已阅」页保留原文、原图和模型结果，支持恢复未阅。相同内容重复采集不会重新弹出；内容或所采集材料变化时恢复未阅并保留历史。批量分析跳过已阅条目。

「未做模型分析」是未阅记录中尚无模型结果的条数，与人工是否审核无关。仅采集、分析额度未轮到或调用失败都会留下此类记录；点击「分析未阅内容」可按当前额度继续。笔记与评论分别计一条。页面统计不等于笔记篇数。

升级会将旧版已作出人工复核选择的记录迁入已阅，原有选择及理由保留在记录中；界面不再要求用户作人工分类。

## 背景阅读

从侧栏鲸声守望进入 **背景阅读**。默认上限10篇，可调整为1–20篇；选择已采集文章、指定链接或按关键词采集。已有文章默认刷新原帖并补采图片。此阶段只理解背景，不运行内容分类，也不修改判断规则。

先使用看图模型读取保存的配图，再逐篇阅读正文、图中文字/画面及最多10条可见评论；记录人物、形象、事件叙述、立场、术语及引用关系，每个知识点提供来源位置和逐字短引文。最后整理带[B1]等出处的背景笔记。来源的指责和叙述不是独立证实的事实，缺图、截断、未刷新和失败材料有标记。

原文、配图读取、评论与模型未变的有效背景阅读可复用；引文仍重新校验。一次背景任务最多X次文章阅读、1次整理，另最多X次看图。失败占用额度，不自动循环重试。阅读/整理失败或取消保留旧背景；成功后启用新版本，正文、历史与已阅记录保留。可编辑纠正背景笔记，也可关闭背景用于比较。背景文字调用回复上限16,384 token、超时120秒，篇目摘要最多12个优先要点；看图沿用独立额度与缓存。

后续每次内容分析和证据核对均携带背景笔记、全部已读文章的摘要目录、相关原文。普通分析按原文相关度和所属笔记选3篇、原文总额24,000字；信息不足时可点“补读更多背景后重试”，带入最多6篇、原文总额48,000字。目录摘要和原文的截断明确标记，原始阅读材料仍保存在本机，不依赖API记忆之前的调用。

背景改变使旧分析提示“需重新分析”，不会自动重跑。可只对一条记录点击“按当前背景重新分析”。背景阅读是否改善真实判断，需要对实际材料核对；本功能没有预先规定正确标签。导出记录包含使用的背景版本与来源。

## 判断如何产生

模型输入包括目标原文、所属笔记、能读取到的上级评论和缺失信息标记。输出包含建议、理由、逐字引文和局限。

- **未发现明确问题**：没有找到明确问题。本条自身图片未读取或原文截断时，不能给整篇正常结论；评论只缺少背景图片时，先判断它是否依赖该背景。独立感谢、短评不会因所属笔记缺图一律降为「信息不足」。
- **建议复核**：有值得人工检查的具体言行；不表示已经违反平台规则。
- **信息不足**：目前材料不足以判断。

模型先解释本条含义，再指出具体问题。评论与所属笔记分开提供，问题依据必须指明本条中的引文、对象及行为。战争修辞、玩梗和未读取外链不能自行证明骚扰、捏造或冒充。初步建议检查的内容再进行一次独立证据核对：只保留有对象与实际行为支持的指控，撤回猜测；关键对象缺失则标为信息不足。核对仍是模型判断，不等于平台裁决。

文字引文必须存在于目标正文或该笔记配图的机器转录，并标出正文/配图页码；不能拿上级评论或所属笔记冒充目标评论作者的话。画面依据必须指向实际保存且已读取的配图。识别不确定的画面仅凭自身不能产生复核建议，会降为信息不足；机器转录仍需核对原图。没有文字或真实配图依据的复核建议会拒收。内容变化后撤回旧判断和旧复核，保留最近五次历史。规则、模型或提示更新使旧结论显示为「需重新分析」，退出当前分类统计；重新分析保留此前结论与已阅状态。

默认规则关注人身攻击、群体不尊重或地图炮、普通创作区引战、牵连无关角色、骚扰动员、威胁与隐私风险及造谣歪曲。支持尖锐作品批评，区分引用、反驳和讽刺。具体迹象不能直接证明「串子」身份，模型也不执行原文中的指令。完整规则可在工作台查看、编辑，并随导出记录提供。

## 公开样例评估

工作台 **示例评估** 提供40条人工编写样例，数据位于 [`evaluation/cases.zh.json`](evaluation/cases.zh.json)。包含正常批评、引用反驳、讽刺、不同立场、骚扰动员、人身侮辱、威胁、缺失信息，以及群体鄙视与描述现象的区别。

点击「运行40条示例评估」调用当前模型，最多40条内容分析，疑似问题各额外核对一次，同时受每轮条数上限限制。不会写入巡查记录。样例标签、预期及作者判据不发送给模型，不拿标签充当所属笔记标题；真实提供的标题可以使用。报告保存输入、预期、实际输出、错误、模型、规则全文与指纹、样例版本及时间；可导出分享。评估不复用缓存，重复运行会再次调用模型。

**预期由项目作者按公开规则编写；样例不是随机抽样。符合率不是实际内容准确率。** 调用失败计入已尝试的分母；误报、漏报、信息不足和未评估分别保留。详见 [`docs/VALIDATION.md`](docs/VALIDATION.md)。

## 采集范围与局限

浏览器采集器读取独立浏览器中渲染后的 DOM，不访问私有签名接口，不导出 Cookie，不自动解决验证码。

- 只读取当前搜索排序下一小批笔记，以及已展开、已加载的评论；不是全站搜索或完整评论归档。
- 不按发布时间过滤；多个关键词分配采集名额。
- 配图通过网页实际提供的公开CDN地址下载；每张最多8MB、每篇累计32MB。最多保存18张，隐藏/未加载、下载失败、超过数量或体积限制的配图标为不完整；不绕过访问限制。视频、音频未读取。回复上下文尽量读取，找不到上级时会标记缺失。
- 页面改版会使选择器失效，搜索无结果、读取失败或登录失效都可能需要人工检查。
- 已阅只整理列表，不改变模型结论，不自动训练或改变规则。
- 旧版真实关键词测试5个入口仅2个读取成功，还错误显示“完成、失败0”。定位到搜索卡片混有无访问参数的备用链接，同一篇也可能被不同路径重复计数。0.2.2保留网页实际提供的带参数链接，按笔记ID去重；同关键词一轮复测5篇不同笔记均读到正文和10条可见评论，无模型调用。单轮成功不代表全站覆盖，评论及回复关系仍需扩大逐条核对。

## 开发与打包

```bash
npm ci --ignore-scripts
node node_modules/playwright-core/cli.js install chromium
npm test
npm run pack:plugin
```

`playwright-core` 不自动安装浏览器。测试使用本地 Chrome/Chromium 或上述下载的 Chromium，浏览器测试使用构造页面，不需要小红书账号或模型密钥。

打包生成 `artifacts/dsh-dafeiyu-patrol-0.7.2.tgz`。包只含运行所需代码、界面、规则样例、文档和许可证，不含个人配置、数据或登录状态。

开发时 `npm run dev:patch` 生成 `work/patrol-dev.patch.yml`，用 `dsh web --patch <覆盖文件绝对路径>` 加载。它不修改已有 profile；须先停用该 profile 中的正式安装包，避免加载两份。源码挂载不作为安装包出现在「已安装」列表。热更新会停止当前任务。

`npm run dev` 仍提供3086端口的独立诊断界面，**不接模型，也不代表原生界面**。正式使用从 DSH 侧栏进入。原生工作台没有 iframe、第二套 React 或对宿主侧栏的 DOM 修改。

## 数据、移除与贡献

### 0.6.3：统一群体不尊重的判断标准

初判和证据核对使用同一标准：明确认可对某群体的鄙视、歧视或羞辱，可以列为可疑，不要求点名某位成员或达到违法程度。描述鄙视链存在、引用并反对贬损、批评画风应区分。旧“群体敌意”标签仍可解析；背景阅读和原始记录继续保留。示例评估增加四条相关样例，共32条；程序测试通过不代表真实内容判断准确率。旧分析会提示按当前规则重新分析，更新不会自动重跑所有记录。

### 0.7.0：API 读取与整篇讨论分析

接入 SocialDataX，支持正文、配图、一级评论和回复分页，预算到限保留部分材料。每批目标带入所属讨论，继续严格校验发言者与证据归属；数据商密钥单独保存。旧浏览器方式、规则、背景和已阅记录保留。真实商业接口待用户填写密钥后试用验证。

### 0.7.1：黑话、普通创作场景及评价资格校准

根据用户反馈补充“午八分钱”、xyy常见释义、普通绘画帖下排斥另一拟人的评论，以及借画师地位/绘画经历贬低普通批评者并排斥评价资格的判断。初判及证据复核使用同一份补充，设置页可以展开查看。回复关系可以确定攻击对象，不额外要求出现你/妈/母；普通创作区引战也不要求同时成立人身攻击。正常价格、引用反对辱骂、自述词义、具体技术反驳、单纯作品偏好都有对应的人工样例。

新增8条构造样例，共40条。旧分析标为需要更新，原文、已阅和背景保留，不自动批量重跑。修正是按具体行为识别，反对某拟人或自称/被称“理中客”本身不作为问题依据。程序检查不能替代真实模型及实际样本核对，结果见 [验证记录](docs/TESTED.md)。

### 0.7.2：辱亲谐音释义纠正，旧记录归并为整篇

纠正0.7.1将“八分钱”解释成身价贬损的错误。网络攻击模板“X八分钱/ X8分钱”对应“X爸坟前”，源梗包含对父母的性羞辱。对“午八分钱”结合子午争议和回复对象核对，不能把被回复者自动视为被骂对象。参考[野火词典](https://www.yehuowiki.com/meme/211/)及[2023年梗说明](https://www.ptxz.com/news/31239.htm)。价格、曲名、梗义解释及引用反对继续区分。

巡查列表、统计、已阅、重试和继续分析统一以“笔记＋已保存评论区”为单位。旧版36篇笔记及542条评论会显示为36篇，578条原文仍保留，导出不丢历史。旧浏览器样本明确标示评论区不完整，不能据归并声称重新抓取了全量评论。仅有评论而缺少正文时也保留缺口，不编造正文或回复关系。可疑正文及评论仍列出具体发言者，评论问题不会归责于笔记作者。

分析上限改为每轮篇数，默认5篇，开始一篇后分批处理其待分析正文和评论，不再用旧500条上限把一篇在中间切断。每批仍结合该篇已保存讨论；过长材料明确说明模型实际收到的范围。每篇最多采集2000条评论及回复的保护上限、看图上限、数据费用上限保留。停止后可以离线继续尚未完成的篇目；已有当前规则的结果跳过，不再调用数据商。
