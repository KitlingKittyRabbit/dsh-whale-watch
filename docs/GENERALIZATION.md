# 鲸声守望：通用舆情工具改造方案

0.8.2补齐巡查Agent的工作台操作，配置制作助手仍只保存草稿；0.8.1已精简为巡查、专题、设置三个页面；0.8.0已完成背景、黑话和术语的可载入配置、内置DS配置与配置制作Agent；0.7.9已完成小红书API搜索选项。下述多专题隔离、趋势统计和其他平台仍是后续设计。

## 产品定位

保留“鲸声守望”作为名称，围绕“舆情观察与讨论环境维护”组织功能。用户新建专题时，填写关注对象、关键词、搜索范围、判断规则和背景资料。当前DS拟人争议变成可选择的预设，不再是所有专题默认加载的背景。

既保留整篇正文和评论区的语境，又按具体条目提供原文、判断理由及来源。舆情的负面观点不自动等于攻击；针对具体言行的检查结果与观点、情绪等观察信息分别呈现。继续支持人工查看、已阅及原文跳转。

## 首先完成：通用基础与专题预设分离

0.8.0已把背景笔记、来源、术语别名/释义和语境说明拆到JSON文件。通用模型提示不再固定加入DS黑话，初判和核对共用当前载入资料。内置DS配置可直接导入；现有背景和规则不覆盖，新安装没有固定的DS语境。默认行为类别及输出校验仍固定为当前七类。

配置制作Agent只整理材料、校验和保存草稿，用户在“专题”页查看并采用；没有自动替换或采集工具。导入/卸下可撤销，不自动重跑旧结论。详见 [专题配置指南](CONTEXT_CONFIG.md)。目前是单份启用配置，还不是多个专题的数据隔离。

## 再完成：多个专题互相隔离

每个专题独立保存关键词、搜索排序、时间范围、规则、黑话说明、背景版本、预算、已阅、任务及分类结果。采集原文可以共享存储，但分析、历史、已阅、去重范围必须区分专题。否则同一笔记在专题A查过，可能被专题B误排除；B也可能使用A的黑话或结论。

每轮任务固定保存专题与配置快照；切换专题不改变正在运行的任务。补读图像、换背景或规则时保留旧结论，不自动扩大分析范围。只有用户明确选择重新分析才重算已有结果。

## 舆情观察与具体行为检查

保留现在的“可疑／其它”作为讨论行为检查结果。后续另加关注对象、观点摘要、正负面表达、主要议题等观察信息，不挤进这两个结果分类。允许负面评价、作品批评及正常分歧作为普通舆情记录，不据此生成不合理行为结论。

先保留已定义的行为检查类型；要支持自定义类别，必须一起改模型输出、校验、统计、筛选和评估样例，不能只放一个可编辑文本框。

## 采集与覆盖

先把小红书作为一个数据来源，稳定现有API、导入、图片和评论关系。下一步改为按专题组织候选池，为不同关键词留出名额，避免第一个关键词占满；区分发布日与近期新增评论，避免把“旧笔记的新讨论”误当作不存在。

“最热”必须明确依据点赞、评论或收藏哪一项。有限搜索结果与预算无法保证全站覆盖；看板应列出实际搜索页数、已读篇数、漏采原因、评论缺口与费用。当前时间筛选是供应商限定的相对范围，没有任意日期区间；本地过滤只能筛已有结果，不能补足没搜到的内容。

未来其他平台通过统一的数据来源适配器提供正文、作者、链接、发布时间、互动数、评论及回复、附件和覆盖说明。有可用来源后再实现与验证，不能因供应商网站列出平台名称就宣称插件已支持。浏览器自动采集保持停用，直到另行解决此前风控问题。

## 推荐实施顺序

1. 已完成：背景／术语配置分离、DS文件导入与制作助手；继续用实际样例检验理解准确性。
2. 专题数据隔离、配置快照与已有数据迁移。
3. 关键词候选名额分配、采集覆盖及预算展示。
4. 观点摘要与趋势统计，然后再接新平台。

每阶段用可公开的人工样例检查跨专题污染、引用反驳、普通负面观点与攻击的区别；同时检查真实内容的读取完整性。程序测试只证明流程行为，不能替代语义准确率评估。
